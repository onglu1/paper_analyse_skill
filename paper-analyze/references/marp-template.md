# Marp PPT 大纲规范

## 核心定位

基于精读笔记的思考逻辑，生成适合展示的 PPT 大纲。与精读笔记的逻辑一致，但内容更精炼、文字密度更低、每页聚焦一个要点。

输出格式为 Marp Markdown，可直接用 `marp --html` 转为 PDF/PPTX。

## 输入与输出

- **输入**：精读笔记（markdown）+ images/ 目录
- **输出**：Marp 格式的 markdown 文件
- **总页数**：10-15 页
- **讲解时间**：10-15 分钟

## 结构逻辑

| 部分 | 页数 | 说明 |
|------|------|------|
| 封面页 | 1 | 标题、作者、venue |
| 背景与动机 | 1-2 | 领域现状、现有方法的不足 |
| 问题定义 | 1 | 形式化定义或核心挑战 |
| 方法总览 | 1 | 架构图 + 一句话概括 |
| 方法细节 | 2-4 | 每个关键模块 1 页 |
| 实验设置 | 1 | 数据集、基线、指标 |
| 实验结果 | 2-3 | 结果图/表 + 关键发现 |
| 总结与启发 | 1 | 贡献总结 + 对自己研究的启发 |

## 格式规范

### Frontmatter

```yaml
---
marp: true
theme: default
paginate: true
size: 16:9
---
```

### 页面分隔

每页用 `---` 分隔。

### 页面结构

每页包含：
- 页标题（`##` 级别）
- 要点（不超过 4 条 bullet）
- 图片引用（如有）

### 图片格式

| 用途 | 语法 | 说明 |
|------|------|------|
| 右侧图片 | `![bg right:40%](images/xxx.png)` | 文字在左，图在右 |
| 居中图片 | `![w:600](images/xxx.png)` | 图片居中显示 |
| 全屏背景 | `![bg](images/xxx.png)` | 图片铺满整页 |

图片路径统一使用相对路径 `images/xxx.png`。

## 写作原则

1. **一页一要点**：每页聚焦一个核心观点，但要把这个观点讲清楚
2. **讲清思路**：不要只列标题式的 bullet，要包含"为什么这么做"和"怎么做"的逻辑。每条 bullet 可以是 1-2 句完整的短句，让听众不看讲稿也能理解
3. **字数控制**：每条 bullet 控制在 20-40 字，比精读笔记精简但比纯标题丰富
4. **图片优先**：能用图说明的不用文字
5. **逻辑串联**：方法细节页要体现"发现问题 → 突破口 → 设计方案"的递进逻辑，不要只列结论
6. **每页 4-6 条 bullet**：允许比纯演示文稿多一些内容，因为这是大纲而非最终 PPT

## 完整示例

以下是一个虚构论文的 Marp PPT 示例，展示所有格式用法：

```markdown
---
marp: true
theme: default
paginate: true
size: 16:9
---

## CoopAgent: 基于角色分工的多智能体协作框架

**作者**：Zhang Wei, Li Ming, Wang Fang
**会议**：ICML 2025

---

## 背景：多智能体系统的挑战

- 现有多智能体系统缺乏有效分工机制
- 同质化 agent 导致冗余计算
- 通信开销随 agent 数量指数增长
- 缺少动态任务分配策略

![bg right:40%](images/background.png)

---

## 动机：为什么需要角色分工？

- 人类团队通过角色分工提升效率
- 专业化降低单个 agent 的认知负担
- 角色约束减少无效通信
- 分工使系统可扩展性更强

---

## 问题定义

- 输入：任务描述 $T$，agent 集合 $A = \{a_1, ..., a_n\}$
- 目标：学习角色分配函数 $R: A \times T \rightarrow \text{Role}$
- 约束：最小化通信开销，最大化任务完成率
- 核心挑战：角色空间未知，需自动发现

---

## 方法总览

- 三阶段框架：角色发现 → 任务分配 → 协作执行
- 角色通过对比学习自动聚类
- 任务分配基于匈牙利算法
- 协作执行采用受限通信协议

![bg right:40%](images/framework.png)

---

## 方法细节：角色发现模块

- 突破口：agent 行为轨迹隐含角色信息
- 设计：对比学习 + 聚类
- 将历史轨迹编码为角色嵌入
- 通过 K-means 自动确定角色数量

![w:600](images/role_discovery.png)

---

## 方法细节：受限通信协议

- 突破口：并非所有 agent 都需要互相通信
- 设计：基于角色的通信图
- 同角色 agent 共享局部信息
- 跨角色仅传递关键决策信号

![w:600](images/communication.png)

---

## 实验设置

- 数据集：StarCraft II, MPE, Google Football
- 基线：MAPPO, QMIX, RODE, MAVEN
- 指标：胜率、通信量、收敛速度
- 消融：角色数量、通信带宽、agent 规模

---

## 实验结果：主实验

| 方法 | StarCraft II | MPE | Football |
|------|:---:|:---:|:---:|
| MAPPO | 72.3 | 85.1 | 61.2 |
| QMIX | 74.8 | 83.6 | 58.7 |
| RODE | 78.1 | 87.2 | 64.5 |
| **CoopAgent** | **83.6** | **91.4** | **70.8** |

- 所有环境上均取得最优性能
- 大规模场景优势更明显

---

## 实验结果：通信效率

- 通信量减少 60% 而性能不降
- agent 数量翻倍时通信仅增长 30%
- 角色约束有效过滤冗余消息

![bg right:40%](images/comm_efficiency.png)

---

## 总结与启发

- 贡献：提出角色分工的多智能体协作框架
- 核心创新：自动角色发现 + 受限通信
- 启发：角色机制可迁移到 LLM-based agent
- 局限：角色数量需预设上界
- 未来：动态角色演化、开放环境适应
```

## 注意事项

- 图片路径必须使用相对路径 `images/xxx.png`
- 图片来源于精读笔记的 images/ 目录，文件名保持一致
- 公式使用 LaTeX 语法，Marp 原生支持 KaTeX
- 表格保持简洁，列数不超过 5 列
- 如果论文图片不足，优先用文字 bullet 代替，不要编造图片引用
