# 论文精读笔记结构规范

本文件定义了精读笔记的生成规范。子 agent 在生成笔记时必须严格遵循此结构。

---

## 一、笔记整体结构

精读笔记由以下六节组成，按顺序排列：

1. 概览
2. 论文怎么定义问题
3. 相关工作
4. 方法与架构
5. 评测
6. 总结

---

## 二、各节详细说明

### 第一节：概览

概览需要讲清楚两件事。注意：在实际生成的笔记中，这两部分**不使用** a./b. 子标题，用段落自然组织。

**第一件事：论文想要解决的核心问题是什么，包括这个核心问题是如何简化的。**

关键是把论文的研究对象从大领域一步步聚焦到具体问题，讲清楚每一步的边界。读者看完就知道"这篇论文关注的到底是哪一类具体问题"，而不是停留在一个模糊的大方向上。

示例思路：一篇做 MAS 系统的文章 → MAS 系统有很多种 → 这篇文章的研究对象是多个 agent debate 的（每个 agent 生成答案然后互相参考后再生成下一轮，重复迭代后生成最终答案）→ 但这个问题设置跟一般的 workflow 类 agent 系统又不一样 → 讲清楚区别在哪里。

**第二件事：简要讲讲论文提出的方法是什么。**

方法的主干是什么，用了什么算法。不需要展开细节，让读者对方法有一个整体印象即可。

### 第二节：论文怎么定义问题

详细讲解概览中的问题定义部分。包括但不限于：

- 公式化定义（如适用）
- 任务定义
- 约束条件
- 优化目标
- 输入输出是什么

注意：有的论文不适合用公式化定义，可以不写。重点是让读者知道作者到底在优化什么、输入输出是什么。

### 第三节：相关工作

简要梳理相关方向的脉络，重点讲清楚本文方法和已有工作的区别在哪里。不需要面面俱到，聚焦于帮助理解本文定位。

### 第四节：方法与架构

**组织原则：先讲方法的总览，再分开来讲细节，不要一上来就扎进某一个具体子问题。**

理解论文方法的拆分逻辑：

```
论文的背景问题
  → 论文提出的方法发现了什么样的突破口（如何一步一步解决问题）
    → 针对每个突破口做了怎么样的设计解决的
      → 这些设计用到了什么算法
```

递归拆解示例：MAS系统的调优可以先生成拓扑再调优 prompt → 生成拓扑又遇到什么难题（比如发现实验过长，则先训练了一个预测器用来预测脆弱性）→ 调优 prompt 又有什么难题又用了什么方法 → 如此递归拆分。

**本节通常包含：**

- **4.1 方法总览（或架构总览）**：论文通常有架构或算法结构图，需要把图片找出来放在这里，结合图片介绍。如果论文不是某个具体方法而是一个大的架构，则将"方法总览"替换为"架构总览"。
- **4.2 方法细节**：下面拆分出若干 4.2.1、4.2.2 等更细节的子节。每个子节对应一个突破口及其解决方案，按递归拆解的逻辑组织。

### 第五节：评测

按以下顺序组织：

1. **实验设置**：先讲清楚 baseline 怎么选的、benchmark 怎么选的
2. **实验设计**：实验是怎么设置的，为什么要这么设置
3. **实验结果**：讲具体实验结果时需要引用原文的实验结果图/表

### 第六节：总结

- 如果用户有调研目的：结合调研目的讲讲这篇论文的意义
- 如果没有调研目的：讲讲这篇论文的简要总结

## 三、概念提取规则（glossary.md 生成）

### 执行时机

概念提取在撰写笔记前完成，先通读全文。提取完成后**先写 glossary.md，再写精读笔记**。

### 提取 5 类概念

1. **Baseline 方法名**：用户可能没读过的对照组论文中的方法
2. **数据集名称**：及其测试什么能力
3. **技术术语和缩写**：论文中出现的专业术语
4. **相关工作中提到的方法**：related work 里引用的方法
5. **论文自定义的新概念/新量**：本文首次提出或定义的概念

### glossary.md 条目格式

每个条目包含：

- 全称（如有缩写）
- 1-3 句直觉解释
- 在本文中的角色

### 双链标记

精读笔记主干中术语首次出现时用 `[[glossary#概念名|概念名]]` 双链标记，引用到 glossary.md 中对应的标题节。`|` 后面是阅读模式下显示的文本，通常就是概念名本身。

---

## 四、图片插入原则

- 原文中有的图尽量在合适的地方插入到笔记中
- 插入时需要结合图片原本的题注理解图片的含义
- 根据有哪些图片再微调精读笔记的结构
- **MinerU 公式图片过滤**：只保留在 Markdown 原文中被明确引用、且有明确图注或明确含义的图片；纯公式截图不保留

---

## 五、Frontmatter 格式

每篇精读笔记的开头必须包含以下 YAML frontmatter：

```yaml
---
title: 论文标题
year: 发表年份
venue: 具体发表地方（如 AAAI 2025, NeurIPS 2024, arXiv 等）
paper_type: system / method
tags:
  - 论文笔记
  - 精读
---
```

`paper_type` 取值说明：
- `system`：论文主要贡献是一个系统或框架
- `method`：论文主要贡献是一个算法或方法

## 六、glossary.md 示例

```markdown
---
title: <论文标题> 概念速查
tags:
  - glossary
---

## GRPO
Group Relative Policy Optimization。一种基于组内相对排序的策略优化算法，不需要额外训练 critic model，直接用同组样本的相对 reward 来估计 advantage。

**本文角色：** baseline 方法之一，用于对比 RL 训练效果。

## G-Designer
一种用图神经网络自动生成 MAS 通信拓扑的方法（来自 xxx 论文）。输入任务描述，输出 agent 间的连接关系。

**本文角色：** 相关工作中的拓扑生成方法。
```

---

## 七、生成流程总结

子 agent 生成精读笔记时按以下顺序执行：

1. 通读论文全文
2. 提取概念，生成 glossary.md
3. 确认论文中有哪些图片可用
4. 按六节结构撰写精读笔记，在合适位置插入图片
5. 术语首次出现时添加 `[[glossary#概念名|概念名]]` 双链标记
6. 添加 frontmatter
